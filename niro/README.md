# Niro profile for the Surveyor platform (Niro-started local runtime).

`niro find --config-dir=niro` starts the app from the current checkout with
`harness/start.sh`, seeds a deterministic baseline with `harness/seed.sh`, and
tests the listener authorized in `scope.yaml`. No `--url` is passed, so Niro
owns the full start/stop/seed/reset lifecycle.

The harness is deliberately committed so every run reproduces the same
baseline:

| Operation | Script | What it does |
| --- | --- | --- |
| start | `harness/start.sh` | Builds the checkout, boots workerd on `0.0.0.0:8788` with local bindings, waits for health |
| stop | `harness/stop.sh` | Stops the process group started by `start.sh` |
| seed | `harness/seed.sh` | Creates two submissions via the public intake API and writes `credentials.yaml` + `fixtures.yaml` |
| reset | `harness/reset.sh` | Stops, wipes workerd local state, starts fresh, and re-seeds |

`credentials.yaml` and `fixtures.yaml` are generated by the seed; they are
gitignored. Everything under `harness/run/` (PID file, logs) is runtime state
and is gitignored too.

The application is bound to `0.0.0.0` on purpose: a listener on `127.0.0.1`
only is not reachable from Niro's attack container on native Linux Docker.
